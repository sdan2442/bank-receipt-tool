# 银行回单拆分与重命名工具

这是一个面向 Windows 10/11（64 位）的本地离线桌面工具。扫描件、文件名、OCR 文本、坐标、处理记录和日志不会上传；程序未接入任何云 OCR、云 API 或远程大模型。

## 公开源码预览

当前应用版本为 v0.3.10，默认使用双 mobile 模型，结果进入人工复核。上下布局发票的购买方标签被拆字时可能留空，详情见 RELEASE_NOTES.md。

源码以 AGPL-3.0 发布，第三方组件按各自许可证使用。安装与模型下载在开发准备阶段进行，应用处理业务单据时使用本地模型。许可证全文见 LICENSE，依赖清单和对应源码说明见 THIRD_PARTY_NOTICES.md。

公开仓库提供应用源码。含运行库和模型的 Windows 离线包将在二进制依赖的许可与对应源码材料核对完成后通过 Release 发布。

## 已实现

- PDF 采用“渲染一页 → 拆分 → OCR → 原子保存 → 写入断点”的流式处理；支持 PDF、JPG/JPEG、PNG、TIFF、BMP，支持多选文件和递归选择文件夹。
- EXIF 方向、90°页面方向纠正、180°双向 OCR 择优、轻微倾斜校正和 CLAHE 对比度增强；确认 90°方向后先保存转正工作图，再对完整页面重新 OCR，首次横倒识别的文字和坐标全部丢弃；清晰页跳过昂贵降噪，低质量页缩放后快速降噪。
- 多张回单可按完整边框拆分；空白分隔漏掉一个切点时，若已有切点落在对齐边框之间，继续验证各框。无边框页面可根据重复标题与文字坐标划分区域并复用整页 OCR，仅在必要时补识别局部。各裁片均须识别出回单类型、日期、付款人和金额。无法可靠拆分时保留整页，确认有多张的页面以“多回单待拆分”命名并提供建议框。
- 默认使用 PP-OCRv5 mobile 检测 + mobile 识别（快速），可切换 mobile 检测 + server 识别（均衡）或 server 检测 + server 识别（高精度）。三种模式均为本地 CPU 推理，显式指定模型名称与路径并禁用模型来源联网检查。
- 关键词定位、OCR 坐标邻近关系、正则、日期/金额格式校验、金额上下文排除及中文大小写金额一致性校验；付款人户名和收款人户名按各自标签及表格单元格独立提取，并支持 `户名/戶名`、`账号/帳號` 等常见 OCR 繁简变体，禁止跨左右栏拼接；支持跨 OCR 行组合中文大写金额，并按“元/角/分”坐标重组金额表格、排除孤立数字格。
- 字段提取前先用本地 OCR 文本分类为银行回单、发票、承兑汇票正面/详情、承兑汇票背书页或未知类型。分类规则位于 `config/bank_rules.yaml`，文件类型、置信度和依据写入界面、Excel 与审计 JSON。
- 支持电子发票及常见增值税发票版式，可与银行回单混合处理。发票按 `发票号_购买方_金额_开票日期.pdf` 命名，金额取价税合计（小写），日期为 YYYY-MM-DD。发票号按文本保存，保留前导零。缺失或不唯一的字段留待人工确认，四个字段均可在复核窗口更正。程序按页处理发票，扫描件中同页多张可用手动拆分。
- “电子银行承兑汇票、电子商业承兑汇票、增信信息、票据行为人详细信息”等复杂连续票据版面强制回退为一份整页单据并进入复核；不可靠裁切框会被清除，不在预览中显示错误红框。
- 完成识别后若存在至少两个承兑汇票页面，会先打开“承兑汇票页面合并”窗口；合并页序严格采用人工勾选的先后顺序，未勾选页面和原输出全部保留。合并件进入多页人工核对窗口，可逐页翻看并保存为一个原子写入的多页 PDF；合并记录及页序会写回本地历史任务。
- 在复核窗口可手动画框拆分，也可采用建议框。裁片按框选顺序写入待复核并复用原页框内的 OCR。主界面的“手动合并页面 / 排序”接受未知类型页面，合并 PDF 按勾选顺序排列。原页和原输出均保留。
- 对小字表格中被 OCR 拆成单字的“付／款／人”和“收／款／人”，按同列坐标重组并在各自栏内关联户名。
- OCR 文字框方向会二次校验 90°页面；密集表格干扰初始直线检测时，会比较顺/逆时针的完整页面 OCR。转正时按新宽高转换建议裁切框，规范并校验 `x1 < x2`、`y1 < y2`，预览和最终 PDF 使用同一方向。
- 日期、付款人、金额各自置信度；缺失、低置信度、有效多候选、金额不一致和低拆分置信度自动进入待复核。付款人按“付款人→户名→单元格”的表格关系定位，自动组合单元格内的跨行长户名以及 mobile 常见的“付款＋人”分框标签，并排除收款方、账号、币种等相邻字段；无法补全且以“有限公”等残缺词尾结束的名称强制复核。交易金额大写按所在行绑定，排除手续费、余额等金额。
- 付款人结果若包含“支行、分行、营业部、信用社、农商行、村镇银行”等金融机构特征，或名称以“银行/银行股份有限公司”等结尾，会保留识别值但强制进入人工复核，防止把相邻的开户行误当付款人；“银行设备科技有限公司”等普通企业词组不会仅因中间出现“银行”而触发。
- v0.3.7 将“付款人/收款人开户行、开户银行、账号、卡号”等更具体字段置于户名关键词之前排除，避免其中的“付款人/收款人”子串被误当户名标签；mobile 漏识别户名标签时，可按同排坐标从开户行左侧保守恢复公司名称，语义置信度最高 82%。银行机构复核同时覆盖付款人与收款人，“业务回单（收款/付款）”标题也作为银行回单强特征。
- mobile 识别产生无效中文大写金额序列时，仅丢弃该金额候选并将页面标记为“中文大写金额格式异常”待复核；不会把字段转换异常误报为 OCR 失败。真正的字段解析异常同样保留完整 OCR 文本与坐标并进入复核，只有模型推理本身失败才进入 `failed`。
- 选择“快速（mobile 检测 + mobile 识别）”时，所有 OCR 成功的结果均强制进入人工复核，并显示“快速模式（纯 mobile）识别结果需人工复核”；均衡和高精度模式仍按字段与置信度规则决定状态，真正的 OCR 推理失败仍进入 `failed`。
- 中文 PySide6 界面、后台线程、页级阶段进度、暂停、停止并保存、取消、断点继续、指定页码处理、结果表、人工复核和 Excel 处理记录。
- 可从输出目录加载已完成、已停止或已取消的历史任务，直接恢复结果表和人工复核界面，不重新初始化 OCR、不重复处理页面；人工确认后的字段与状态会原子写回任务记录，再次启动仍保留复核进度。
- 输入文件/文件夹显示为可勾选清单；支持全部勾选、全部取消、移除未勾选和清空清单。开始处理时固定已勾选项的快照并锁定输入区，之后的界面操作不会改变正在运行的任务。
- 输出先写临时文件再原子改名；永不覆盖同名文件，自动追加 `_02`；默认不移动、不修改原文件。
- 待复核 PDF 附带本地 JSON（OCR 全文、坐标、置信度和候选值）；日志对长账号和身份证号脱敏。

## 安装（开发环境）

需要已安装 64 位 Python 3.11，然后在 PowerShell 中执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\setup.ps1
.\run.ps1
```

`setup.ps1` 会自动创建 `.venv`、安装依赖、从 Paddle 官方源下载四个模型、校验文件、执行一次 OCR 加载测试，再模拟断网执行第二次 OCR。无需手动下载模型。

## 离线模型

统一位置：`models/`。程序启动时检查 `inference.json`（或旧格式 `inference.pdmodel`）与 `inference.pdiparams`，缺失时直接报错，不会触发在线下载。

| 名称 | 用途 | 发布系列 | 官方来源 | 许可证 |
|---|---|---|---|---|
| PP-OCRv5_server_det_infer | 高精度文字检测 | Paddle 3.0 inference | `paddle-model-ecology.bj.bcebos.com/paddlex/official_inference_model/paddle3.0.0/` | Apache-2.0 |
| PP-OCRv5_server_rec_infer | 高精度文字识别 | 同上 | 同上 | Apache-2.0 |
| PP-OCRv5_mobile_det_infer | 快速文字检测 | 同上 | 同上 | Apache-2.0 |
| PP-OCRv5_mobile_rec_infer | 快速文字识别 | 同上 | 同上 | Apache-2.0 |

运行库锁定为 PaddlePaddle 3.2.2、PaddleOCR 3.3.2。来源与许可：[PaddleOCR 官方仓库](https://github.com/PaddlePaddle/PaddleOCR)（Apache-2.0）、[PaddlePaddle 官方仓库](https://github.com/PaddlePaddle/Paddle)（Apache-2.0）、[PaddleOCR 官方模型列表](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/model_list.md)。每个下载压缩包的 URL、大小和 SHA-256 会记录到 `models/models_manifest.json`；可运行 `python scripts/verify_models.py` 复核。

## 运行与输出

运行 `.\run.ps1`。默认输出到“桌面\银行回单处理结果”：

```text
output/
├─ success/
├─ review/          # PDF、复核 JSON 和 .previews 本地预览
├─ failed/
├─ logs/
│  ├─ app.log       # 错误日志不写 OCR 全文，账号/身份证脱敏
│  └─ ocr_audit/    # 本地审计 JSON：OCR 全文、坐标与置信度
├─ .jobs/           # 本地断点文件：源文件指纹、已完成页及结果
└─ processing_results.xlsx
```

双击待复核行可查看回单图片、OCR 全文、候选值、来源页码、字段置信度并修改后保存。批量 OCR 进行中可复核和保存已经处理完的页面。手动拆分及合并在本次处理结束后开放。

手动拆分时可在页面上点选裁片，或从列表中选取被遮挡的框。拖蓝框内可移动，拖边或角的圆点可调整范围。使用“新增裁片”可从已有框内部开始画框。裁片允许重叠，每张 PDF 都保留自己框内的完整图像。

程序重启后，先把“输出目录”指向原处理结果目录，再点击“加载历史任务 / 继续复核”，选择对应文件即可恢复复核清单。如果当前目录没有历史记录，程序会提示选择以前的处理结果目录。此操作只读取 `.jobs` 和 `.previews` 本地文件，不会加载 OCR 模型，也不会重新识别原 PDF。

选择文件或文件夹后，只有清单中已勾选的项目会被处理。误选项目可直接取消勾选，或点击“移除未勾选”；任务运行期间输入清单会锁定，任务结束后自动恢复。

默认命名规则为 `{交易时间中的日期}_{付款人户名}_{交易金额}.pdf`。日期优先提取“交易时间”对应值中的日期部分，例如 `2025-12-1710:21:45` 规范化为 `2025-12-17`；仅在没有有效交易时间时，才回退到交易日期、记账日期等配置关键词。OCR 选择 180°结果时会同步旋转复核预览和最终 PDF，不修改原文件。

### 逐页处理与断点恢复

任务方式可以选择“从上次中断处继续”“重新处理全部页面”或“处理指定页码”。指定页码支持 `13-32`、`1,3,8-10` 等格式。程序每完成整页（包括该页所有裁切的 OCR 和输出）后，才在 `output/.jobs/` 原子写入检查点；恢复前会核对原文件路径、大小、修改时间和 SHA-256，以及模型和配置签名。原文件发生变化时不会错误续接。

“暂停”保留当前进程；“停止并保存进度”完成当前页后写入可恢复断点；“取消任务”保留已完成输出，但不会被默认的断点继续自动选中。进度条显示已完成页数，并在状态文字中区分预处理和 OCR 阶段。

## Windows 打包

安装完成且测试通过后执行：

```powershell
.\build.ps1
```

输出为 `dist\BankReceiptTool_v0_3_10\银行回单工具.exe`。这是 PyInstaller 目录包，`models/`、`config/`、Paddle/PaddleOCR、PySide6 和 Python 运行库会一并收集。请将整个目录解压到纯英文路径（如 `D:\BankReceiptTool_v0_3_10`），首次启动无需联网。

## 新增银行规则

编辑 `config/bank_rules.yaml`。通用字段词放在 `common`；文件类型特征放在 `document_types`；特定银行可以在 `banks` 下新增银行名及关键词/空间规则。分类器和字段提取器只读取配置，不需要改界面。建议为每个新增版式增加一份脱敏 OCR 行测试，验证类型、付款人/收款人区分与金额上下文。

## 已知限制与排查

- 一页多张回单采用保守策略；无明显边框、边界检测冲突、互相重叠或背景复杂时会保留整页进入复核，不会删除原件。
- 承兑汇票的出票、承兑、背书链等专用字段保留在 OCR 全文和坐标中，由人工复核，尚未自动生成结构化背书清单。
- 手写、印章遮挡、极低分辨率和严重透视变形需要人工复核。当前不做银行专用深度版面模型训练。
- 模型缺失：运行 `setup.ps1`；只允许官方域名，网络受限时应授予访问权限，不要替换第三方镜像。
- DLL 加载失败：安装最新 Microsoft Visual C++ 2015–2022 x64 运行库，并确认使用 64 位 Python 3.11。
- 内存或速度受限：优先选择“均衡（mobile 检测 + server 识别）”；“快速”占用最低但小字和复杂表格准确率通常较低，高精度 server 模型体积和 CPU/内存占用最高。
- 崩溃或断电：已完成 PDF 仍保留；`.tmp.pdf` 不会被当成成功结果，原文件不受影响。
